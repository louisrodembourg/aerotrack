# aerotrack: working conventions

Real-time vehicle/pedestrian detection + tracking on drone video, judged against an
embedded latency budget (`configs/project.yaml`: 25 FPS end-to-end, batch 1). The
deliverable is the accuracy/latency trade-off analysis, not a model. Everything in the
repo (code, comments, docs) is in English.

## Commands

```bash
make setup         # uv sync --frozen
make data          # download + convert + viz + TrackEval self-check, all datasets
make data-min      # VisDrone-DET only (enough for smoke and baseline)
make smoke         # ~1 min training + eval on 100 images, local device
make baseline      # COCO YOLO zero-shot on VisDrone-DET val, then README table
make test          # offline tests; `uv run pytest --run-network` adds network tests
make lint
uv run aerotrack --help
scripts/remote_train.sh configs/train/<cfg>.yaml [--set key=value]   # CUDA box
uv run aerotrack kaggle push <cfg> [<cfg2>] --slug <slug> [--suffix probe] [--dry-run]
uv run aerotrack kaggle push <cfg> --slug <slug> --resume <run-id>   # continue an interrupted run
make w3-eval | w4-eval | w4-p2-eval | w5-sahi-eval | w6-track-eval | w6-track-tuned-eval | w6-keyframe-eval   #
make w6-track-tune   # tracker thresholds on MOT sequences unseen by the detector (never test-dev) evaluate a week's pulled runs on test-dev, then README
uv run aerotrack kaggle status|pull <slug>                           # Kaggle 2 x T4
```

## Rules

- **Raw data is never modified.** Raw files are read-only after extraction; processed
  images are symlinks. Never `.resolve()` a processed image path: it leads into
  `data/raw/` (see DECISIONS.md).
- **Every number comes from a tracked run.** Training and evaluation go through
  `aerotrack.experiments.start_run` (config, commit + diff, seed, device, environment,
  metrics, artifacts). README tables are generated by `aerotrack readme-table` from
  `reports/*/results.json`, never typed.
- **Every latency figure carries its context:** device name, torch / ONNX Runtime /
  TensorRT versions, and the Jetson power mode (`runtime/env.py` collects them).
  Latency is batch 1, images pre-decoded, device-synchronised per stage.
- **One pipeline for accuracy and latency** (`aerotrack.inference.Detector`). A new backend
  (TensorRT, C++) plugs in there, not in a side script.
- **Nothing assumes CUDA.** Device = `auto` (cuda > mps > cpu); an explicit device that is
  unavailable is an error, never a silent fallback.
- **Class mappings are explicit** (`configs/data/class_maps.yaml`): every source id is
  mapped, excluded with a reason, or ignored, and a test enforces it.
- **Ignored regions follow each dataset's official rule** (`data/ignore.py`): masked at
  training, dropped on both sides at evaluation.
- **When unsure about a format, an API or a licence, read the source or the docs, then
  record it** in DECISIONS.md. Don't guess.
- **Fine-tuned models are reported on VisDrone-DET test-dev**, never on val: val selects
  the checkpoint. Val numbers from training are monitoring only.
- **Tests never write to `data/`**: an autouse fixture redirects paths to tmp and fails if
  `data/processed` changed. Synthetic data generators live in `tests/fixtures/` only.

## Layout

```
configs/      project.yaml (budget), data/ (sources, class maps), train/, eval/
src/aerotrack/
  data/       download, per-dataset converters, ignore rule, class maps, visualisation
  inference.py  Detector (torch | onnxruntime)
  eval/       detection (COCO), latency, tracking (TrackEval), harness, track_harness, report
  track/      Kalman filter (from scratch), ByteTrack, TrackingPipeline (keyframe mode)
  train.py    Ultralytics training with masked dataset + tracked run
  experiments.py, runtime/ (device, env fingerprint, git, seed), ultra.py
docker/       Dockerfile.cuda
  remote/     Kaggle launcher (kernel template + push/status/pull)
scripts/      remote_train.sh
reports/      generated reports (committed); viz/ is git-ignored (dataset images)
```

Record every non-trivial choice in DECISIONS.md: the alternative rejected and why.
